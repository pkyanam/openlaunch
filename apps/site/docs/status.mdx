## Hosted software

- The public site is deployed at `www.openlaunch.dev`; the apex redirects to `www`.
- The site documentation and read-only documentation MCP are deployed separately from the device-control service.
- Clerk Google owner sign-in and the admitted agent OAuth flow have been exercised. The agent connection was approved by the user.
- OAuth scopes and device capability grants are separate. Owners must approve capabilities for each device and agent.
- The hosted API uses SQLite-backed Durable Objects keyed to the verified Clerk workspace identity.
- Custom manifest functions are schema-validated, exposed as device-specific MCP tools after an owner grant, and checked against the live grant at invocation.
- On deployed commit `6e317a0`, legacy combined SDK-token acceptance verified stable attachment retry after a deliberately lost response: the retry returned the same child device credential, and the master token was not persisted on the device. This predates the current attach-only `ol_sdk_` setup-token and separate `ol_agent_` agent-credential contract.
- Legacy combined-token tests verified no grants by default. An ungranted action and agent self-grant both return 403; attachment beyond the owner-set device limit returns 429. The owner can grant device health and a custom `custom.echo` function; changing the manifest clears those grants. These historical results do not describe a new combined-token flow.
- Automated permission and persistence tests cover the current split setup-token/API-connection routes and persistent grants.
- An authenticated Node adapter received WebSocket wake hints and then rechecked work over HTTPS. A software fixture returned health in 601 ms and `custom.echo` in 508 ms. These timings verify the software path only, not a physical device.
- Hosted revocation acceptance on the legacy combined-token flow confirmed that revoking that token denied its agent requests while leaving the paired device identity intact. Explicit device revocation then denied polling and reuse of an event ticket issued before revocation. Temporary acceptance devices and tokens were retired. Under the current split contract, setup-token revocation does not revoke an issued child credential; agent-connection revocation stops agent access and removes its grants.
- Broadcast requests support up to 20 devices and return an independent result for each device.

## Software and firmware behavior

- SDK attachment, scoped grants, action expiry, revocation and queued/received/terminal command outcomes are implemented. The Go Pi and Uno runtimes have durable result journals; tested software behavior does not establish physical hardware operation.
- The Go Pi health profile reports process health. The opt-in [Linux host profile](/linux) implements up to 15 locally configured host functions, including real filesystem and subprocess operations. Its software acceptance is separate from physical Pi testing. GPIO and display control are not implemented.
- Uno R4 firmware supports health, the built-in LED and matrix text.
- WebSocket notifications are payload-free wake hints for the Node and native Go adapters. The ticket is short-lived and used in the authenticated handshake; the adapter fetches queued work over HTTPS. A 10-second HTTP polling fallback remains. Generic Uno and ESP32 adapters use HTTP polling; the Roomba sketch polls every second and drains pending work promptly.
- Simulated device results are identified as simulated; they do not demonstrate a physical action.
