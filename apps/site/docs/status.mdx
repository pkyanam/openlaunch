## Hosted software

- The public site is deployed at `www.openlaunch.dev`; the apex redirects to `www`.
- The site documentation and read-only documentation MCP are deployed separately from the device-control service.
- Clerk Google owner sign-in and the admitted agent OAuth flow have been exercised. The agent connection was approved by the user.
- OAuth scopes and device capability grants are separate. Owners must approve capabilities for each device and agent.
- The hosted API uses SQLite-backed Durable Objects keyed to the verified Clerk workspace identity.
- Custom manifest functions are schema-validated, exposed as device-specific MCP tools after an owner grant, and checked against the live grant at invocation.
- Broadcast requests support up to 20 devices and return an independent result for each device.

## Software and firmware behavior

- Enrollment, scoped grants, action expiry, revocation and queued/received/terminal command outcomes are implemented.
- The Go Pi runtime reports process health. GPIO and display control are not implemented.
- Uno R4 firmware supports health, the built-in LED and matrix text.
- Simulated device results are identified as simulated; they do not demonstrate a physical action.

## Physical device acceptance

Physical acceptance remains open. Pi and Uno checks for network access, TLS and time synchronization, provisioning, power loss and reconnect have not been completed. Uno command journaling and bounded streaming response parsing need work before expanding its functions; Pi result-retry reconciliation also remains open. Neither device promises exactly-once physical execution.

## Try openlaunch

Follow [local setup](/setup), run the software checks, and use the trusted HTTPS test path for deliberate [Uno R4](/uno-r4) or [Pi](/pi) hardware acceptance. Website hosting and hosted identity do not establish that a physical board is connected.
