title: Raspberry Pi 4
description: Install the openlaunch agent on a Raspberry Pi 4 with one owner-issued SDK token and private device credentials.
---

## Install and pair

In **Connections**, create a token with device attachment enabled. On Raspberry Pi OS running on a Raspberry Pi 4 Model B (4 GB or 8 GB), run:

```sh
curl -fsSL https://www.openlaunch.dev/install-pi.sh | bash
```

When prompted, enter the SDK token; the prompt is hidden. The installer derives the workspace from the token and attaches the Pi. It downloads the matching ARM binary over HTTPS and verifies its SHA-256. It supports 64-bit ARM64 and 32-bit ARMv7 systems. You need `curl` and Python 3; it does not need Go or Node.js, `sudo`, boot changes or a firmware flash.

The installer stores the executable at `~/.local/bin/openlaunch-device` and the private per-device credential at `~/.config/openlaunch/device.json`. It never stores the SDK token and stops if either file already exists. If attachment is interrupted, rerun the installer with the same token within 10 minutes. If that window has passed, inspect **Devices** before starting another attachment.

After installation, start the agent with the command printed by the installer. It runs in the foreground; press Ctrl-C to stop it. Run the same command to start it again. The optional systemd unit is in the [source repository](https://github.com/pkyanam/openlaunch/blob/main/devices/pi/openlaunch-device.service); setting it up requires a service account and paths.

When the Pi appears in the console, open its **Access** view and grant the agent only the functions it needs. The grant is separate from the SDK token and expires on its own. See [Pairing and permissions](/pairing).

## Current capability

The Pi runtime reports process health only. GPIO and display control are not implemented. Pairing and a successful software result do not prove physical hardware behavior; see [Verification](/status).

## Build from source

For development, build the Linux binary with Go:

```sh
npm run build:pi
```

Load the SDK token into `OPENLAUNCH_SDK_TOKEN` from your secret store, then attach and start the agent:

```sh
./openlaunch-device --attach --url https://www.openlaunch.dev --config "$HOME/.config/openlaunch/device.json"
./openlaunch-device --config "$HOME/.config/openlaunch/device.json"
```

The token is used only during attachment. Keep the child device credential file private and outside Git. Do not use `--simulate` for hardware acceptance.
