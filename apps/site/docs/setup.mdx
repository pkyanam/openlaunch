## Run the local bridge

Install Node 24+ and Go matching `devices/pi/go.mod` (currently 1.27.1). [Downloads and upstream docs](/resources).

```sh
git clone https://github.com/pkyanam/openlaunch.git
cd openlaunch
npm ci
npm run build --workspace @openlaunch/web
npm run test:e2e
```

The test pairs a simulated device and checks command results, persistence and revocation. It doesn't touch hardware. If you already have a checkout, preserve local changes.

Start the console with two random, temporary tokens. These commands generate them locally without printing them or putting their values in shell history:

```sh
export OPENLAUNCH_OWNER_TOKEN="$(node -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("hex"))')"
export OPENLAUNCH_AGENT_TOKEN="$(node -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("hex"))')"
npm run dev:local
```

Open `http://127.0.0.1:8788`. Copy the owner token into the console's development session field using your local password/clipboard workflow; on macOS, `printf %s "$OPENLAUNCH_OWNER_TOKEN" | pbcopy` copies it without displaying it. Clear your clipboard afterward. The console keeps the token in page memory.

In the console:

1. Create an enrollment for **Uno R4 WiFi** or **Pi**.
2. Follow the [Uno guide](/uno-r4) or [Pi guide](/pi) to pair it within 10 minutes.
3. Grant `local-agent` the device's health capability, request health, and inspect the completed result.

Pairing registers the device; the grant lets the agent use it. Add LED or matrix grants only for the Uno. [Full pairing and permission rules](/pairing).

## Local MCP

The endpoint is `http://127.0.0.1:8788/mcp`. Configure your host's supported environment-variable bearer-token setting using `OPENLAUNCH_AGENT_TOKEN`. Tools are `list_devices`, `request_device_health`, `show_text`, `set_led`, `get_action` and `cancel_action`.

The agent needs a separate capability grant. It cannot enroll devices or approve itself. Queued and received actions are intermediate outcomes.

## Real boards require HTTPS

A board cannot reach your Mac's loopback address. Use a trusted HTTPS reverse proxy you control, targeting `http://127.0.0.1:8788`, and set `OPENLAUNCH_PUBLIC_ORIGIN` to its exact bare HTTPS origin before starting the bridge. Open the console through that origin. This exposes the development API for your test window; close the proxy afterward.

Do not disable TLS verification. R4 requires port 443, a trusted hostname and a valid clock. This temporary developer setup does not implement public ChatGPT OAuth.

Continue with [pairing](/pairing), [R4 setup](/uno-r4) or [Pi setup](/pi). Detailed platform instructions live in the repository's [Mac handoff](https://github.com/pkyanam/openlaunch/blob/main/docs/MAC-HANDOFF.md).
