## Connect an agent and device

1. [Open your console](https://www.openlaunch.dev/console/) and continue with Google.
2. In **Devices → Add device**, create a device setup token. It uses the `ol_sdk_` prefix, expires after 10 minutes by default, and attaches one device by default.
3. Run the hosted setup menu on your Pi or the computer beside your board:

   ```sh
   curl -fsSL https://www.openlaunch.dev/setup.sh | bash
   ```

   Choose the adapter. You need curl and Python 3; Node adapters also need Node 24+. USB setup configures already-flashed firmware. The helper checks downloads against the current manifest.

4. [Connect your agent](/agents). When the device appears, open **Access**, choose that connection and its functions, set an expiry, and **Save grant**. ChatGPT through Executor needs an Executor grant; the direct ChatGPT grant belongs to a different connection.

The device setup token only pairs hardware; it cannot authenticate an agent or call MCP tools. Create a separate `ol_agent_` API connection for SDK agents, or connect ChatGPT and Codex through MCP OAuth. In either case, an owner must approve each device's functions. A grant can expire or remain active until revoked. Inspect the action receipt for the result. To add hardware behavior, see [Build your own functions](/functions).

## Run a local developer console

You need [Node 24+ and Git](/resources). On macOS or Linux, run:

```sh
curl -fsSL https://www.openlaunch.dev/install.sh | bash
```

The installer downloads the source, builds the console, and starts the bridge. It does not flash a board or change cloud resources. You can [read the hosted script first](/install.sh). The [GitHub copy](https://raw.githubusercontent.com/pkyanam/openlaunch/main/scripts/install.sh) is the backup. A new installation checks out the deployed source commit from the hosted manifest, so it matches the checked website build.

Open **http://127.0.0.1:8788**. On macOS, your owner session key is already on the clipboard: paste it into the session field and select **Connect**. On Linux, copy the `token` value from `.cache/local/owner.json` in the installed checkout. Keep that file private. Your session key is a password for your console; never give it to an agent.

The default installation is `~/.local/share/openlaunch`. An existing checkout is reused without resetting your files. To stop the bridge, press **Ctrl-C**. To start it again:

```sh
cd ~/.local/share/openlaunch
npm run start:local
```

## Add your board

Create a device setup token in **Devices → Add device**, then use the [Uno guide](/uno-r4), [Pi guide](/pi), [Linux host guide](/linux), [Home Assistant guide](/home-assistant), or [custom adapter guide](/sdk). The older one-use enrollment flow remains for existing integrations.

For a real board, the bridge needs a trusted HTTPS address the board can reach. Your Mac's loopback address only works on that Mac. See [network setup](/troubleshooting#my-board-cannot-reach-the-bridge).

## Connect your agent

Follow [agent connections](/agents). Grant that connection **health** for your device in **Access**, then ask it to check the board's health and inspect the result. Add LED or matrix access when you want the Uno to use those functions.

A grant names the agent connection, device, allowed functions, and optional expiry. Pairing alone does not give an agent permission.

## Work on the source

Already cloned the repository? Run `npm run setup` from its root. The installer needs only Node and Git. Building or testing the Pi agent also needs [Go](/resources); flashing an Uno needs [Arduino CLI](/resources).

Use `npm run check` for shared API, permissions and protocol tests. `npm run test:e2e` runs a simulated device through the local bridge; it requires Go and does not operate physical hardware. Platform details are in the [Mac handoff](https://github.com/pkyanam/openlaunch/blob/main/docs/MAC-HANDOFF.md).
