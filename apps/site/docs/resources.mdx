## openlaunch downloads

[Install ol on PATH](/install-cli.sh) and follow the [CLI guide](/cli). The [native endpoint reference](/reference) and [OpenAPI contract](/device-api.json) cover the authenticated device service; [agent setup](/agents) covers MCP.

Run `curl -fsSL https://www.openlaunch.dev/setup.sh | bash` for the setup menu. Installers are served by openlaunch from the same checked GitHub commit as the website, updated automatically by CI. GitHub hosts the source code and CI build artifacts. The Linux host installer downloads an ARM64, ARMv7 or x86-64 native binary; the Pi health installer downloads an ARM binary and verifies its checksum. Raspberry Pi OS remains the operating system; openlaunch does not provide a flashable OS image.

- [Source ZIP (main)](https://github.com/pkyanam/openlaunch/archive/refs/heads/main.zip) — moving branch; use a commit archive for reproducibility.
- [CI builds and Pi binary artifacts](https://github.com/pkyanam/openlaunch/actions/workflows/ci.yml) — open a successful run and download `openlaunch-pi-binaries`. GitHub sign-in may be required. Build outputs are developer artifacts, not hardware-verified releases.
- [Release page](https://github.com/pkyanam/openlaunch/releases) — no versioned binary release is currently published.
- [Roomba provisioning script](/downloads/provision-roomba.py) and [ArduRoomba source](https://github.com/pkyanam/ArduRoomba) — the custom Uno sketch exposes clean, dock, pause, movement, sensors and outputs.
- [R4 provisioning script](/downloads/provision-uno.py) — inspect it before using it with `npm run provision:uno`.
- [Stock firmware source](https://github.com/pkyanam/openlaunch/tree/main/firmware) and [build profiles](https://github.com/pkyanam/openlaunch/blob/main/docs/UNO-R4-PROFILES.md).
- [Pi Go agent and systemd service](https://github.com/pkyanam/openlaunch/tree/main/devices/pi).

[Install the Linux host harness](/install-linux.sh), [install the Pi agent](/install-pi.sh), [download the Codex plugin](/downloads/openlaunch-plugin.zip), or [install the local development bridge](/install.sh). A [GitHub copy of the local bridge installer](https://raw.githubusercontent.com/pkyanam/openlaunch/main/scripts/install.sh) is available as a script backup; the site build pins this link to the deployed source commit. The [Uno provisioner](/downloads/provision-uno.py) and [ESP32 provisioner](/downloads/provision-esp32.py) configure boards over USB. Source and CI artifacts are linked from GitHub. There is no hosted device token or login needed to read the docs.

`/downloads/installers.json` lists hosted installer checksums and commit-pinned GitHub script backups. For hosted SDK archives, it lists SHA-256 checksums and commit-pinned source locations. It does not list GitHub binary archive backups. Verify downloads against the manifest before running or installing them.

## Device and agent SDK

[Download the JavaScript/TypeScript SDK](/downloads/openlaunch-sdk.tgz) or follow the [Device and agent SDK guide](/sdk) for separate agent API access and device setup. The package includes agent and device clients, typed manifests, action receipts and custom function publishing. The [SDK source](https://github.com/pkyanam/openlaunch/tree/main/packages/sdk) is the reference implementation. Native firmware can use the same [HTTP contract](/api); the maintained Uno adapter is separate from the Node runtime.

## Shared packages

The packages are in the monorepo and are not published to npm yet. See [all package sources](https://github.com/pkyanam/openlaunch/tree/main/packages), including protocol, auth, core, HTTP and MCP. The [architecture guide](/architecture) explains their boundaries.

## Integration discovery

The [integrations.sh listing](https://integrations.sh/www.openlaunch.dev/) maps the device API, MCP, `ol` and the separate public documentation services. Machine-readable discovery is published at `/.well-known/integrations.json`, `/.well-known/api-catalog`, `/.well-known/mcp/server-card.json` and `/.well-known/agent-skills/index.json`, generated from the same deployment. The canonical `/openapi.json` describes device control and its distinct credential purposes; `/docs-openapi.json` describes the public read-only docs API. Discovering these surfaces does not create device grants.
